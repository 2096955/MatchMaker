## Learned User Preferences

- Ship SCUDO matching UI from the understand-anything `packages/dashboard` (vendored `dashboard-dist` at `/demo/`, including in `jpmc-port`); not a bolt-on in `MatchMaker/frontend/` `/mapping` or generic ingestion-console pages.
- Synthetic or mock demo data is acceptable when unmistakably labelled ILLUSTRATIVE and the narrative is coherent; incoherent mock taxonomy presented as real bank data is unacceptable (e.g. Marketing domain for LSEG/ICE/S&P).
- Matching UI must tell an expositional story (vendor → ETL → matcher → confidence gate → persist); every stage should explain itself in context.
- MatchMaker only — no Defra, no project switches, no commits unless explicitly asked.
- Multi-phase ontology/rights work (DCAT P0→P4; catalogue-rights UML gap Phases A→C) stops after each phase for review with changed files, verification commands, and pass/fail counts before continuing; on a dirty worktree preserve unrelated uncommitted changes and edit shared files narrowly (e.g. retain existing SSE heartbeat edits in `backend/routes/mapping.py`).
- Self-improvement loops must keep the standard outside the optimizer's reach: the proposer may only change prompts/skills/rule artifacts, never evaluation cases, held-out split, metric definitions, thresholds, publish gates, confidence bands, or the evaluator; promotion is an atomic versioned pointer move over immutable content-addressed artifacts with automatic rollback, never an in-place rewrite; defer a GNN until a leakage-safe, production-scale labelled corpus exists.
- Keep matcher diffs narrow and bounded; preserve flag-gated compatible defaults and dense-score-only / BM25-nominator-only invariants; verify the design spec's residual evidence gaps in code (matching bands, enrichment shapes, Neptune precedent) before editing affected files.
- Require production-grade dogfooding of the claimed path before declaring work complete (including Playwright visual checks for dashboard `/demo/` claims); failed required checks block completion claims; do not juxtapose deterministic stub pass counts with Opus/agentic-loop claims in ARB evidence.
- Citrix/JPMC handoffs: process + full absolute clickable file links, or one anchored file a human can retype (every change is typed in by hand, so minimise edit surface and cite exact `file:line`); comment out (don't delete) MySQL/FalkorDB/Neptune call sites; document local-run with file-backed memory when Aurora is unreachable. Re-verify links, line numbers, and claims against live files before shipping.
- JPMC-facing Mapping + Verifier agents must carry the system weight: Claude Opus 4.8, full agentic loops/reasoning/tool use, high token budget; every HITL teach must trigger fail-loud learning (no swallowed write errors); deterministic stubs are local/CI only, not the Atlas production path; if Bedrock Opus is unavailable for dogfooding, Cursor model is an acceptable agentic-loop test stand-in.
- Do not claim agents can solve catalogue/rights UML (Dataset/Contract/Policy/CDM) without typed schemas, skills, and tools wired to that model.
- Keep the root README simple and clear for business readers; preserve useful repository-map wording and avoid replacing it with dense engineering tables or unnecessary churn.
- Capone is the Cognizant-owned environment: fully local, portable, no Citrix port; JPMC-side politics/personnel are out of scope for Cognizant packaging. The demo must be one-click (`run_demo`), boot the whole stack, offer three upload points (vendor / contract / dataset) exercising the many-to-one story, and expose agent chat that demonstrates reasoning and guides the user. This repo stands on its own — borrow good UX ideas from other front ends, never their code or stale thresholds.

## Learned Workspace Facts

- SCUDO matching UI lives in `Understand-Anything/understand-anything-plugin/packages/dashboard`; `MatchMaker/frontend/` is the Data Ingestion Framework console only. Two graph schemas: **KnowledgeGraph** (dashboard via `backend/scudo/build_matching_graph.py`) and **MatchPayload** (`GET /api/mapping/graph` via `build_match_payload()`); JPMC day-one port scopes fixture regen and MatchPayload out; Azure path is optional/undecided.
- Canonical CDAO IRIs: `jpmorgan:data:cdao:*`; forbidden in shipped artifacts: `urn:cdao:*`, bare `cdao:*`, and Marketing domain nodes; pre-existing `test_provenance.py` Marketing failures are unrelated to rights-model / jpmc-port work.
- Matcher confidence bands (canonical): PASS ≥0.80, BORDERLINE 0.70–0.80, FAIL <0.70 per `backend/scudo_mapping_mcp/config.py`. Taxonomy JSON source of truth: `backend/scudo/fixtures/cdao_catalogue.json`; sync to dashboard via `backend/scudo/scripts/sync_matching_graph_to_dashboard.sh`.
- Do not edit Codex-owned files: `backend/scudo/data-platform.yaml`, `build-pipeline.yaml`, `template.yaml`; console AWS deploy uses `infra/scudo-poc-*.yaml` via Citrix CloudShell (`scudo-poc-console-build`) and publishes `dashboard-dist/` to S3 `/demo/` with CloudFront invalidation. Binding specs: matching `docs/superpowers/specs/2026-06-24-scudo-matching-frontend-spec.md`; DCAT `docs/superpowers/specs/2026-07-03-dcat-ontology-matching-design.md`; catalogue/rights UML `docs/superpowers/specs/2026-07-13-catalogue-rights-uml-gap-analysis.md` (`ContentDeliveryModel` 11 values; PROVISIONAL is `HAS_DUTY`-only).
- Backend verification cwd: `MatchMaker/backend/` with `PYTHONPATH=.` for pytest and import smoke (`jpmc-port/` likewise with `PYTHONPATH=.`); the bare `pytest` wrapper can report "No tests collected" misleadingly — invoke `python3.11 -m pytest -vv` directly for genuine collection evidence.
- Slim JPMC rewrite lives in `jpmc-port/` (Capone `backend/scudo/` left intact); default agents are Bedrock Opus 4.8 (`us.anthropic.claude-opus-4-8`, `max_tokens=128000`) with agentic tool loops; `SCUDO_LOCAL=1` is deterministic e2e only (not Opus evidence); matching dashboard vendored at `jpmc-port/dashboard-dist/` served at `/demo/` via `run_local.py` (:5001); Capone A/B via `run_ab_compare.py` with Capone arm `python -P backend/scudo/scripts/ab_capone_arm.py` (`jpmc-port/ab_capone_arm.py` is retired). Its agents are not wired to Capone catalogue/rights UML fields (Bedrock alone does not cover Dataset/Contract/Policy/CDM), `orchestrator.py` returns `Outcome.RETRY` with no caller re-attempting, and its candidate-membership / vendor-IRI checks are advisory rather than the hard publish gates Capone has.
- Live skill promotion is `aurora_memory.preflight_skill_promotion` → `matching_self_improvement.validate_promotion`; HITL decisions call `aurora_memory.learn_from_teaching` with fail-loud writes; `skill_gate.py` is not imported on the live path. Automatic promotion requires boundary-supplied trusted evidence and recomputes policy thresholds; legacy/unprotected artifacts cannot auto-promote. Canonical owner is `backend/scudo/matching_self_improvement.py`; its byte-identical JPMC copy is parity-guarded—never let them drift.
- Capone local-run is measured, not inferred: `start_local.py` (or the one-click `run_demo.py` = Flask + Streamlit, `run_cognizant.py` = Flask only with env set before importing `app.py`; guide `COGNIZANT_RUN.md`) runs the whole demo with NO Docker, NO Postgres, NO FalkorDB, NO Neptune, NO AWS. MySQL is already GONE (zero imports); FalkorDB/Neptune are lazy-imported and untouched; `boto3` imports are all lazy. `frontend/dist/` and `dashboard-dist/` are **vendored**, so the React console `/app/` and dashboard `/demo/` need no Node/npm — they 404 only because `SCUDO_SERVE_FRONTEND_DIST` / `SCUDO_SERVE_DASHBOARD_DIST` are unset. DB pages use `CONSOLE_DB_BACKEND=sqlite` → `backend/db_sqlite_fallback.py`. The "only one page opens" symptom is ENV/PORT, not DB: `start_all.sh` runs `app.py` without the local env so the auth gate 401s every `/api/*`, and macOS AirPlay squats on :5000. Reviewer decisions survive a restart; ingested frames do not (re-ingest, then the precedent is reused).
- THREE independent dev-write gates exist and are NOT interchangeable — `SCUDO_VERDICT_ALLOW_DEV` (HMAC signing key), `SCUDO_PERSIST_ALLOW_DEV_WRITES` (persistence MCP), and `SCUDO_AUTH_ALLOW_DEV_WRITES`; without the last, `POST /api/mapping/decision` 403s while reads and matches still work, so Approve/Reject looks silently broken for no visible reason. Matching also refuses to match before ingest (`frame_not_found` 404) — that is the frame gate working, not a defect.
- Matching is **many-to-one** and this is verified, not assumed: every contract is scored against the full catalogue with no exclusive assignment, so two vendors' contracts can both map to the same dataset, and approving one leaves the other untouched. Precedents are keyed per `(vendor, product_id)`; `vendor_signature` keys on the contract **name** (fallback product_id), so identical names share a small rank boost (0.02/approval, capped 0.10) — a ranking nudge, never an auto-approval.
- Agent chat lives in `backend/scudo_mapping_mcp/chat.py` (bedrock + scripted backends over the same six tools) and is surfaced as Streamlit step 04; the scripted responder is keyword-routed and is a no-AWS stand-in, not evidence of agent reasoning. Multi-vendor contract fixtures are at `sample_data/demo/`. Verify Streamlit by driving real widgets with `AppTest` from `streamlit.testing.v1` (note `at.session_state.get(...)` is unsupported — index it); servers started from the agent shell are reaped when the tool call returns, so the agent cannot host a browser-reachable server.
- "Aurora" is three unrelated systems, do not conflate them: console CRUD (psycopg direct, `CONSOLE_DB_*`); the matching store; and agent memory (RDS **Data API**, `SCUDO_AURORA_*`, not reachable from Flask/Streamlit). The matching store now has a FalkorDB-free durable backend — `STORE_BACKEND=scipy_sqlite` (+ `SCUDO_PERSIST_TARGET`, `SCUDO_SCIPY_SQLITE_PATH`), the full 16-method `RetrievalStore` over SQLite with immutable revision-stamped SciPy sparse indexes — and it is the `start_local.py` default; bands stay 0.80/0.70. It is **single-host only** (not shared across ECS tasks/Lambdas) and the AWS templates deliberately remain on FalkorDB; a shared Aurora `RetrievalStore` + shadow cutover is still required for full AWS removal. Separately, `taxonomy_graph.py` is in-memory SciPy sparse (PageRank/shortest-path, read-only, score-blind) with **zero** SQLite — SQLite there is only the console-DB fallback.
- JPMC's Bedrock auth is **`sts.assume_role` + an application-inference-profile ARN**, NOT the bearer token the Cognizant sandbox uses — and neither needs a code change: measured, `BedrockModel` accepts an inference-profile ARN verbatim as `model_id` (so the `us.`/`eu.` prefix logic is bypassed via `SCUDO_BEDROCK_MODEL_ID`), and botocore's credential chain lists `assume-role` second, so an `~/.aws/config` profile (`role_arn` + `source_profile`) suffices for the agent's credential-free `BedrockModel(...)`. The Streamlit preflight only tests the bearer path and shows "No API key set" on a working role — judge by the run, not the sidebar. Their PoC proves `InvokeModel`; the agent needs `InvokeModelWithResponseStream` (ConverseStream), authorised separately.
- The front end is **Streamlit + SQLite** (`streamlit_app.py`, calling the package directly rather than Flask); anchored AWS switch-over handover is `JPMC_AURORA_BEDROCK_FILES.md`. The repo contains **zero Terraform** — all IaC is CloudFormation (`infra/scudo-poc-*.yaml`), so Bedrock/Aurora access is an account-permissions request, not a code change. The JPMC-side "Trade Analyst" Streamlit variant (evidence panel, stale 0.85/0.75 bands, `memory` store, port 8503) exists in no branch or history here — take its ideas, never assume its code is missing from this repo.
- Bedrock needs no code change to switch on (provider factory in `backend/scudo_mapping_mcp/agent.py` honours `get_agent("bedrock")`; Streamlit sidebar wires the bearer token). Region/model-prefix agreement is handled by `SCUDO_REGION` driving both the preflight and the `eu.`/`us.` inference-profile prefix in `streamlit_app.py`; module defaults are `eu.`/`eu-west-2` while `shared/bedrock.py` and the CFN templates default `us.`/`us-east-1`, and CFN `BedrockModelId` must match the container's `SCUDO_BEDROCK_MODEL_ID` or IAM denies the invoke. `BEDROCK_REGION` is injected by infra but never read in Python. Streamlit already has the HITL correction loop (Approve/Reject with staleness guard, fail-loud errors) and, since `chat.py`, free-text agent chat; `override` is still not exposed there.
