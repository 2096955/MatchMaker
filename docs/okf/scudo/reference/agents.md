## Learned User Preferences

- Ship the expositional SCUDO matching story (vendor → ETL → matcher → confidence gate → persist) from the understand-anything `packages/dashboard`, vendored at `/demo/` (including `jpmc-port`), not as a bolt-on to the ingestion console; synthetic demo data is acceptable only when clearly ILLUSTRATIVE and coherent, never as implausible bank taxonomy.
- MatchMaker only — no Defra, no project switches, no commits unless explicitly asked.
- Multi-phase ontology/rights work (DCAT P0→P4; catalogue-rights UML gap Phases A→C) stops after each phase for review with changed files, verification commands, and pass/fail counts before continuing; on a dirty worktree preserve unrelated uncommitted changes and edit shared files narrowly (e.g. retain existing SSE heartbeat edits in `backend/routes/mapping.py`).
- Self-improvement loops must keep the standard outside the optimizer's reach: the proposer may only change prompts/skills/rule artifacts, never evaluation cases, held-out split, metric definitions, thresholds, publish gates, confidence bands, or the evaluator; promotion is an atomic versioned pointer move over immutable content-addressed artifacts with automatic rollback, never an in-place rewrite; defer a GNN until a leakage-safe, production-scale labelled corpus exists.
- Keep matcher diffs narrow and bounded; preserve flag-gated compatible defaults and dense-score-only / BM25-nominator-only invariants; verify the design spec's residual evidence gaps in code (matching bands, enrichment shapes, Neptune precedent) before editing affected files.
- Require production-grade dogfooding of the claimed path before declaring work complete (including Playwright visual checks for dashboard `/demo/` claims); failed required checks block completion claims; do not juxtapose deterministic stub pass counts with Opus/agentic-loop claims in ARB evidence; never report a server as "up" on a status check you know only held for the life of the tool call — say plainly that the human must host it.
- Citrix/JPMC handoffs: process + full absolute clickable file links, or one anchored file a human can retype (every change is typed in by hand, so minimise edit surface and cite exact `file:line`); comment out (don't delete) MySQL/FalkorDB/Neptune call sites; document local-run with file-backed memory when Aurora is unreachable. Re-verify links, line numbers, and claims against live files before shipping.
- JPMC-facing Mapping + Verifier agents must carry the system weight: Claude Opus 4.8, full agentic loops/reasoning/tool use, high token budget; every HITL teach must trigger fail-loud learning (no swallowed write errors); deterministic stubs are local/CI only, not the Atlas production path; if Bedrock Opus is unavailable for dogfooding, Cursor model is an acceptable agentic-loop test stand-in.
- Do not claim agents can solve catalogue/rights UML (Dataset/Contract/Policy/CDM) without typed schemas, skills, and tools wired to that model.
- Keep the root README simple and clear for business readers; preserve useful repository-map wording and avoid replacing it with dense engineering tables or unnecessary churn.
- "Everything wired with a real agent" means every LLM lever actually on, not just the chat backend; prefer silent fallback so a demo keeps moving when a short-lived key dies, but surface which backends are live in the sidebar and judge a run by its reasoning trace, not by a number appearing.
- Capone is the Cognizant-owned environment: fully local, portable, no Citrix port; JPMC-side politics/personnel are out of scope for Cognizant packaging. The demo must be one-click (`run_demo`), boot the whole stack, offer three upload points (vendor / contract / dataset) exercising the many-to-one story, and expose agent chat that demonstrates reasoning and guides the user. Cross-platform handoffs should be credential-free source bundles with Windows/macOS launchers (Python 3.11+ may be assumed); send short-lived keys separately. This repo stands on its own — borrow good UX ideas from other front ends, never their code or stale thresholds.

## Learned Workspace Facts

- SCUDO matching UI lives in `Understand-Anything/understand-anything-plugin/packages/dashboard`; `MatchMaker/frontend/` is the Data Ingestion Framework console only. Two graph schemas: **KnowledgeGraph** (dashboard via `backend/scudo/build_matching_graph.py`) and **MatchPayload** (`GET /api/mapping/graph` via `build_match_payload()`); JPMC day-one port scopes fixture regen and MatchPayload out. Canonical CDAO IRIs are `jpmorgan:data:cdao:*`; shipped artifacts must not contain `urn:cdao:*`, bare `cdao:*`, or Marketing-domain nodes.
- Matcher confidence bands (canonical): PASS ≥0.80, BORDERLINE 0.70–0.80, FAIL <0.70 per `backend/scudo_mapping_mcp/config.py`. Taxonomy JSON source of truth: `backend/scudo/fixtures/cdao_catalogue.json`; sync to dashboard via `backend/scudo/scripts/sync_matching_graph_to_dashboard.sh`.
- Do not edit Codex-owned files: `backend/scudo/data-platform.yaml`, `build-pipeline.yaml`, `template.yaml`; console AWS deploy uses `infra/scudo-poc-*.yaml` via Citrix CloudShell (`scudo-poc-console-build`) and publishes `dashboard-dist/` to S3 `/demo/` with CloudFront invalidation. Binding specs: matching `docs/superpowers/specs/2026-06-24-scudo-matching-frontend-spec.md`; DCAT `docs/superpowers/specs/2026-07-03-dcat-ontology-matching-design.md`; catalogue/rights UML `docs/superpowers/specs/2026-07-13-catalogue-rights-uml-gap-analysis.md` (`ContentDeliveryModel` 11 values; PROVISIONAL is `HAS_DUTY`-only).
- Backend verification cwd is `MatchMaker/backend/` with `PYTHONPATH=.` (`jpmc-port/` likewise); invoke `python3.11 -m pytest` directly because bare pytest can misleadingly collect nothing. Streamlit-prefix tests must snapshot/restore the whole environment: `exec()` of the launcher prefix sets dense-backend and write-gate variables, and restoring only selected keys caused order-dependent leakage.
- Slim JPMC rewrite lives in `jpmc-port/` (Capone `backend/scudo/` left intact); default agents are Bedrock Opus 4.8 (`us.anthropic.claude-opus-4-8`, `max_tokens=128000`) with agentic tool loops; `SCUDO_LOCAL=1` is deterministic e2e only (not Opus evidence); matching dashboard vendored at `jpmc-port/dashboard-dist/` served at `/demo/` via `run_local.py` (:5001); Capone A/B via `run_ab_compare.py` with Capone arm `python -P backend/scudo/scripts/ab_capone_arm.py` (`jpmc-port/ab_capone_arm.py` is retired). Its agents are not wired to Capone catalogue/rights UML fields (Bedrock alone does not cover Dataset/Contract/Policy/CDM), `orchestrator.py` returns `Outcome.RETRY` with no caller re-attempting, and its candidate-membership / vendor-IRI checks are advisory rather than the hard publish gates Capone has.
- Live skill promotion is `aurora_memory.preflight_skill_promotion` → `matching_self_improvement.validate_promotion`; HITL decisions call `aurora_memory.learn_from_teaching` with fail-loud writes; `skill_gate.py` is not imported on the live path. Automatic promotion requires boundary-supplied trusted evidence and recomputes policy thresholds; legacy/unprotected artifacts cannot auto-promote. Canonical owner is `backend/scudo/matching_self_improvement.py`; its byte-identical JPMC copy is parity-guarded—never let them drift.
- Capone local-run is measured, not inferred: `start_local.py` (or one-click `run_demo.py` = Flask + Streamlit; `run_cognizant.py` = Flask only) runs with no Docker/Postgres/FalkorDB/Neptune/AWS. MySQL is gone; optional services and boto3 are lazy. Vendored `frontend/dist/` and `dashboard-dist/` need no Node. DB pages use SQLite. The “only one page opens” symptom is launcher env/auth (and sometimes port contention), not DB. Reviewer decisions survive restart. Local authoritative frames now use a process-cached registry partitioned by an unguessable Streamlit session key so real reruns cannot split writer/reader module state; S3 still uses the canonical frame reader. Taxonomy bootstrap seeds only an empty store, preserving uploaded nodes across reruns/restarts.
- THREE independent dev-write gates exist and are NOT interchangeable — `SCUDO_VERDICT_ALLOW_DEV` (HMAC signing key), `SCUDO_PERSIST_ALLOW_DEV_WRITES` (persistence MCP), and `SCUDO_AUTH_ALLOW_DEV_WRITES`; without the last, `POST /api/mapping/decision` 403s while reads and matches still work, so Approve/Reject looks silently broken for no visible reason. Matching also refuses to match before ingest (`frame_not_found` 404) — that is the frame gate working, not a defect.
- Matching is **many-to-one** and this is verified, not assumed: every contract is scored against the full catalogue with no exclusive assignment, so two vendors' contracts can both map to the same dataset, and approving one leaves the other untouched. Precedents are keyed per `(vendor, product_id)`; `vendor_signature` keys on the contract **name** (fallback product_id), so identical names share a small rank boost (0.02/approval, capped 0.10) — a ranking nudge, never an auto-approval.
- The front end is Streamlit + SQLite (`streamlit_app.py`, calling the package directly rather than Flask); agent chat is step 04 in `backend/scudo_mapping_mcp/chat.py`. Scripted chat is keyword-routed and a no-AWS stand-in, not agentic evidence; it does not truly share the Bedrock agent’s six-tool loop. Multi-vendor fixtures are in `sample_data/demo/`, and uploads accumulate contracts/catalogue nodes. Verify widgets with `streamlit.testing.v1.AppTest` (`session_state.get` is unsupported) and real-browser checks where claimed; shell-started servers are reaped after tool calls.
- "Aurora" is three unrelated systems, do not conflate them: console CRUD (psycopg direct, `CONSOLE_DB_*`); the matching store; and agent memory (RDS **Data API**, `SCUDO_AURORA_*`, not reachable from Flask/Streamlit). The matching store now has a FalkorDB-free durable backend — `STORE_BACKEND=scipy_sqlite` (+ `SCUDO_PERSIST_TARGET`, `SCUDO_SCIPY_SQLITE_PATH`), the full 16-method `RetrievalStore` over SQLite with immutable revision-stamped SciPy sparse indexes — and it is the `start_local.py` default; bands stay 0.80/0.70. Every launcher (`streamlit_app.py` `_best_local_store`, `start_local.py`, `run_cognizant.py`, `run_demo.py`) must agree on `STORE_BACKEND` + `SCUDO_SCIPY_SQLITE_PATH` or Streamlit and Flask split-brain — a UI approval lands in SQLite while the API reads the JSONL journal, looking exactly like memory not working. It enforces referential integrity on taxonomy writes (`parent_iri` must exist), and precedent counts must come from tables `positive_precedents` / `negative_precedents`, never from counting JSONL lines. It is **single-host only** (not shared across ECS tasks/Lambdas) and the AWS templates deliberately remain on FalkorDB; a shared Aurora `RetrievalStore` + shadow cutover is still required for full AWS removal. Separately, `taxonomy_graph.py` is in-memory SciPy sparse (PageRank/shortest-path, read-only, score-blind) with **zero** SQLite — SQLite there is only the console-DB fallback.
- JPMC Bedrock auth is `sts.assume_role` plus an application-inference-profile ARN; the Cognizant sandbox may instead use a short-lived bearer token. `SCUDO_BEDROCK_MODEL_ID` accepts the ARN verbatim, while `SCUDO_REGION` must align model prefix and client region. The Streamlit preflight must independently drain both `InvokeModelWithResponseStream` and direct `InvokeModel`, report ready/degraded/error per operation, and invalidate status after model/region changes. Full agentic operation requires `SCUDO_AGENT_BACKEND=bedrock`, `SCUDO_SPECIALIST_BACKEND=local`, `SCUDO_DENSE_BACKEND=opus`, and an explicit fallback policy. Opus similarity is model-generated input to deterministic bands/publish gates, not “narration only.” Dense scoring is whole-batch all-or-nothing across standard and multi-path routes; fallback-off fails loudly, while fallback-on discards the entire model batch for Jaro. Breaker probe ownership is generation-tokened so stale decisions cannot reset successor probes. The repo uses CloudFormation, not Terraform; account permissions—not code—control AWS access.
